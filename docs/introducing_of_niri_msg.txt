# What is include in niri msg sys?
> A quick and fast way for ipc with an exsist niri instance,valuable for function calling and tool use for agent.
## 1.total:
```sh
niri msg --help
Communicate with the running niri instance

Usage: niri msg [OPTIONS] <COMMAND>

Commands:
  outputs           List connected outputs
  workspaces        List workspaces
  windows           List open windows
  layers            List open layer-shell surfaces
  keyboard-layouts  Get the configured keyboard layouts
  focused-output    Print information about the focused output
  focused-window    Print information about the focused window
  pick-window       Pick a window with the mouse and print information about it
  pick-color        Pick a color from the screen with the mouse
  action            Perform an action
  output            Change output configuration temporarily
  event-stream      Start continuously receiving events from the compositor
  version           Print the version of the running niri instance
  request-error     Request an error from the running niri instance
  overview-state    Print the overview state
  casts             List screencasts
  help              Print this message or the help of the given subcommand(s)

Options:
  -j, --json  Format output as JSON
  -h, --help  Print help
```

1.7 **focused-window** (important for agent context, get current focused window details)
```exp
niri msg -j focused-window
{"id":23,"title":"niri msg -j windows ~","app_id":"kitty","pid":18908,"workspace_id":1,"is_focused":true,"is_floating":false,"is_urgent":false,"layout":{"pos_in_scrolling_layout":[3,1],"tile_size":[942.0,1056.0],"window_size":[942,1056],"tile_pos_in_workspace_view":null,"window_offset_in_tile":[0.0,0.0]},"focus_timestamp":{"secs":8579,"nanos":769012462}}
```
This is the primary command for knowing which window the user is interacting with. It returns the same structure as a single window from `windows`. If no window is focused (e.g., empty workspace), it may return null or an error; handle accordingly.

1.8 **pick-window** - interactively pick a window with mouse and print its info (same output as focused-window)
```exp
niri msg -j pick-window
# (click a window, then output same JSON as above)
```

1.9 **pick-color** - pick a color from the screen with mouse click
```exp
niri msg pick-color
# returns something like "#RRGGBB" (example: #aabbcc)
```

1.10 **action** - perform a window management action (placeholder, details to be filled later)
```exp
niri msg action <subcommand> [args...]
# See `niri msg action --help` for current available subcommands.
# This will be expanded in future for moving/resizing/switching workspaces, etc.
```

1.11 **output** - temporarily change output configuration (resolution, scale, transform) - not persistent
```exp
niri msg output eDP-1 --mode 1920x1080@60 --scale 1.0 --transform Normal
# No output on success.
```

1.12 **event-stream** - continuously receive compositor events (window focus, workspace changes, etc.) as JSON lines
```exp
niri msg event-stream
{"type":"window_focused","window_id":23,...}
{"type":"workspace_switched","workspace_id":2,...}
# Streams until interrupted.
```

1.13 **version** - print the version of the running niri instance
```exp
niri msg version
niri 0.1.0 (commit 123abc)
```

1.14 **request-error** - force an error for debugging purposes
```exp
niri msg request-error
# returns an error string.
```

1.15 **overview-state** - print the current overview mode state
```exp
niri msg -j overview-state
{"is_active":false,"layout":"grid"}
```

1.16 **casts** - list active screencast sessions
```exp
niri msg -j casts
[{"id":1,"output":"eDP-1","application":"obs"}]
```
