资产路径：/home/swordreforge/project/业余项目/bevy_n3ri_os/assets/nori/cakeduel整体实现思路可以总结为：> **先用传统 Web 三件套做一个“规则驱动”的完整游戏原型，把 UI、规则、AI 解耦；之后将核心状态机迁移到 Rust + Bevy，最后给 Nori 接入 LLM 作为人格层。**整体架构：```text                 HTML/CSS/JS Prototype                         |        --------------------------------------        |                  |                 |      UI层              规则层             AI层        |                  |                 |   index.html          rules.js        nori_ai.js   style.css              |                 |                          |                    GameState状态机                          |                          |                    Rust + Bevy ECS```---# 1. 前端阶段目标不是做一次性网页，而是做一个：**可运行 → 可测试 → 可迁移**的游戏模拟器。结构：```textcakeduel-web├── index.html│      UI结构│├── style.css│      忠实还原原界面│├── game.js│      游戏流程控制│├── rules.js│      裁判系统│└── nori_ai.js       Nori决策系统```---# 2. 游戏核心：状态机整个游戏不是事件堆积，而是一台状态机器。例如：```textSTART | |DRAW_HAND | |CHOOSE_ATTACKER | |PLAYER_ATTACK | |AI_DEFENSE | |REVEAL | |RESOLVE | |ROUND_END | |GAME_END```对应：```javascriptGameState.phase```例如：```javascript{ phase:"AI_DEFENSE", playerCake:2, aiCake:1, attacker:"player"}```未来 Bevy：```rustenum Phase {Start,Attack,Defense,Reveal,Resolve,End}```---# 3. 卡牌系统卡牌数据驱动，不写死。```javascriptCard {id,type,}```类型：```SoldierArcherWizardDefenderScientistWolf```规则：```javascriptCardInfo```保存：* 数量* 攻击值* 防御关系* 特殊规则例如：```javascriptwizard:damage=2scientist:block=[wizard]```以后 Rust：```ruststruct Card {id:u32,kind:CardType}```---# 4. 规则系统（裁判）这是最重要的一层。Nori 不决定输赢。玩家也不能决定。只有：```textrules.js```可以。流程：```text攻击声明↓防守选择↓翻牌↓检查真假↓计算防御↓计算蛋糕变化↓判断胜负```核心函数：```javascriptresolveAttack()resolveChallenge()resolveDefense()calculateCake()checkRoundEnd()checkGameEnd()```迁移 Bevy：```rustAttackSystemDefenseSystemResolveSystemWinSystem```---# 5. Nori AI设计Nori不是聊天机器人。它是：```状态机 AI+人格层+未来 LLM```第一层：规则 AI：```text看到状态↓计算可能动作↓选择最高评分动作```例如：防守：候选：```BLOCKACCEPTCHALLENGE```计算：```text收益风险蛋糕数量历史信誉难度参数```输出：```json{ action:"challenge"}```---# 6. 难度设计难度不是增加作弊。而是调整：```text简单：低质疑低骗人普通：平衡困难：高诈唬高判断高风险计算```参数：```javascript{bluffRate,challengeRate,risk,mistakeRate}```---# 7. Bluff（骗人）系统核心：真实牌：```textwizard```声明：```textsoldier```允许。但是：Wolf:特殊：```text不能声明Wolf被质疑必输```所以 AI 出牌：流程：```选择牌↓判断价值↓决定骗人↓生成声明```---# 8. LLM接入位置LLM 不参与规则。错误：```LLM:我要质疑```正确：```状态机:候选:challenge 0.7accept    0.4LLM:调整人格权重```例如：Nori人格：```json{brave:0.8,greedy:0.5,curious:0.7}```影响：* 更敢质疑* 更喜欢骗* 更保守---# 9. Bevy迁移路线最终：## Resource游戏状态：```rustGameState```## Components实体：```rustPlayerCardHandCakeNori```## Systems系统：```rustInputSystemAttackSystemDefenseSystemAISystemResolveSystemRenderSystem```---# 最终架构：```text                 UI                  |                  |             GameState                  |        -----------------        |               |     Rules FSM       Nori FSM        |               |        |          ----------        |          |        |        Personality        |          |        |        LLM(optional)        |    Bevy ECS```---开发顺序建议：### Phase 1✅ HTML/CSS还原界面✅ 卡牌显示✅ 玩家操作### Phase 2⬜ rules.js 完整裁判⬜ 完整三局胜利循环### Phase 3⬜ Nori 三难度⬜ AI记忆系统### Phase 4⬜ Rust Bevy重构### Phase 5⬜ LLM人格层接入这样最终得到的是一个：**Web可玩原型 → Rust游戏核心 → Bevy正式游戏 → LLM驱动角色 AI**的完整演进路线。
